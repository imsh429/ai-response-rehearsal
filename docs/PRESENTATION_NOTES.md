# 응대 리허설 — 발표 구성과 시연 메모

2026-10-21 / 제출용 본문은 [PROJECT_REPORT.md](../PROJECT_REPORT.md).

## 중심 문장

까다로운 AI 고객과 상담하는 것에서 끝내지 않고, 상담사가 조회한 업무 자료와 실제 발언을 근거로 평가하고 같은 상황에서 다시 연습하는 서비스를 만들었다.

역할별 Agent는 고객·평가·코칭을 분리하고, MCP는 업무 근거 접근을 표준화하며, RAG는 확장된 정책 중 필요한 원문을 찾아 평가에 전달한다. 서버는 원문 연결과 최종 검증을 책임진다.

## 10장 구성

| 장 | 제목 | 핵심 내용 | 근거 |
|---|---|---|---|
| 1 | 응대 리허설 | 소속·이름·문제·서비스 한 문장 | 보고서 1절 |
| 2 | 어떤 문제를 풀었나 | 반복 훈련, 평가 이유 확인, 근거 복사 오류 | 보고서 2절 |
| 3 | 사용자는 무엇을 하나 | 조회·상담·평가·재도전 | 라이브 시연 60~90초 |
| 4 | 서비스 구조 | Vue/FastAPI·LangGraph·MCP·RAG·저장·추적 | 보고서 Mermaid |
| 5 | 세 에이전트의 책임 | 고객에게 채점 기준을 숨기고 평가/코칭 입력 분리 | agents.py |
| 6 | 근거 연결 개선 | 모델은 E/M 참조 선택, 서버가 원문 연결 | 실패 테스트·리포트 근거 펼치기 |
| 7 | 정책 RAG | 20개 정책에서 4개 검색·원문 주입·버전 보존 | 검색 화면·rag.py·MCP |
| 8 | 개선 전후 비교 | 전체 20개 문서 기준선 vs 상위 4개 검색, 동일 고정 입력 | 실제 API로 갱신한 BENCHMARK_RESULT.md |
| 9 | 결과와 한계 | 28개 테스트·브라우저 확인과 모델 품질 미확인 구분 | VALIDATION.md·원본 JSON |
| 10 | 배운 점·후속 과제 | 서버/모델 책임 경계, 전문가 평가, 검색 누락·운영 권한 | 보고서 5절 |

실제 API 측정을 못 했다면 8장은 실험 설계와 미측정 항목으로 제시한다. 28개 테스트 통과를 상담 정확도 100%로 바꾸지 않는다. 독립 전문가 검증이나 교육 효과가 확인됐다고 주장하지 않는다.

## 시연 동선

1. OpenAI 모드와 새 배송 지연 훈련을 확인한다.
2. 주문과 이전 상담 조회 후 `출고 전 취소와 배송 지연 보상`을 검색한다.
3. 잘못된 보상 확정 답변을 보내고 고객 스트리밍을 짧게 보여준다.
4. 미리 완료해 둔 리포트에서 정책·상담사 발언 근거와 개선 답변을 펼친다. 실제 평가 대기 시간은 모델에 따라 길어질 수 있다.
5. 개선 답변을 적용한 재도전 결과와 항목별 차이를 보여준다. 학습자의 재도전 비교는 시스템 Before/After 실험과 구분한다.
6. 관리자 실행 ID와 LangSmith trace를 보여준다. 실제 계정 수집이 확인되지 않았다면 구현된 설정만 설명한다.

## 숫자 해석

- Before는 과거 시스템의 실측값이 아니라 동일한 확장 정책 전체를 주입하는 실험 기준선이다. 과거 앱은 시나리오별 3~4개 정책을 직접 연결했다.
- 문서 수 감소는 상위 K 제한의 구조적 결과다. 정확도·비용 개선을 자동으로 의미하지 않는다.
- 문맥 토큰 cl100k는 로컬 토큰 수다. 제공자 과금 토큰은 원본 JSON의 usage를 본다.
- Before 전체 문서의 정책 포함률과 After Recall@4를 같은 검색 지표로 설명하지 않는다.
- --judge 없는 시간은 준비/검색 시간이다. --judge 시간은 정책 판정 포함이며 전체 상담 평가·코칭 지연과 구분한다.
- 자체 작성 12개 예제이므로 반복 3회여도 서로 다른 사례 수는 12개다.
- 오류도 전체 시도 수와 지연에 포함한다. 불리한 결과가 나와도 삭제하지 않는다.

## 기술 질문에 답하기

| 질문 | 답변 방향 |
|---|---|
| Supervisor인가? | 별도 Supervisor LLM 없는 고정 custom workflow. 예측 가능한 작은 업무를 우선 |
| Agent가 직접 도구를 고르는가? | 그래프와 UI가 명시적으로 MCP 호출. Agent는 판단·근거 선택 담당 |
| Resource와 Prompt도 사용하나? | 인터페이스 제공 및 실제 SDK 테스트 완료. 운영 그래프는 Tools 사용 |
| RAG가 무엇을 바꾸나? | 최근 대화로 정책을 검색하고 원문을 평가·코칭에 주입 |
| 환각을 없앴나? | 근거 존재·원문 일치만 검증. 잘못된 해석과 검색 누락 가능성은 남음 |
| 왜 SQLite/Chroma인가? | 로컬 재현과 설치 단순화. 기업 배포에는 권한·격리·운영 DB 필요 |
| 실제 효과가 있나? | 자동 테스트와 데모 흐름 확인. 실제 API 수치·전문가 평가·교육 효과는 별도 검증 |

## 제출 직전

표지 정보를 채우고 실제 측정 결과와 문서 설명을 맞춘다. 공개 GitHub 문서 URL을 인증 없는 요청과 시크릿 브라우저에서 확인한다. 키·실제 DB는 올리지 않는다. 이 문서는 발표 내용 메모이며 PPTX 파일 자체는 아니다.
