## 확인하지 않은 항목

사용자 OpenAI API 키를 받지 않았으므로 실제 OpenAI 인증·과금·응답 품질·모델별 실제 지연은 확인하지 않았습니다. 모의 응답 테스트를 실제 유료 API 성공으로 간주하지 않습니다.

LangSmith 실계정 키가 없으므로 실제 계정으로의 trace 업로드와 워크스페이스/리전 권한은 확인하지 않았습니다. 환경 변수, LangGraph trace metadata, root run ID, SDK usage callback 연동은 구현되어 있습니다.

실제 키로 전체 연동을 빠르게 확인하려면 먼저 OpenAI 모드 서버를 실행한 후 별도 터미널에서 `python scripts/smoke_openai.py`를 실행하세요. 이 명령은 고객 응답·평가·코칭을 실제 호출하므로 API 요금이 발생합니다.

macOS와 Windows 전용 OS에서 설치를 실제 실행하지는 않았습니다. 기본 실행은 플랫폼별 가상환경 Python 명령을 제공하며 MCP 서버도 `sys.executable`로 실행합니다. 검증 환경은 Linux / Python 3.12.14 / Node.js 24.19.0입니다.

## 상용화 전 남은 범위

사용자 로그인, 상담별 접근 권한, 기업별 데이터 분리, 운영 배포/HTTPS, 다중 워커에서의 잠금, 운영 DB·백업, 실상담 전문가 평가 데이터셋과 점수 보정은 현재 범위에 포함하지 않았습니다. 제공 버전은 기능을 시연하고 확장할 수 있는 단일 PC 로컬 MVP입니다.

## 평가 근거 선택 오류 수정

초기 버전은 모델이 source_id와 인용문을 직접 복사하도록 요구했습니다. 실제 응답에서 ID 또는 문장·공백·문장부호가 달라지면 원문 검증이 실패할 수 있었습니다.

수정 버전에서는 서버가 원문을 정확한 부분 문자열로 분할한 evidence_catalog를 만들고, 모델은 E001 등의 짧은 id만 선택합니다. 서버가 source_id와 quote를 연결하므로 모델이 인용문을 다시 생성하지 않습니다. 코칭도 M001 등의 상담사 메시지 참조만 선택하게 하고 original과 message_id는 서버가 연결합니다.

존재하지 않는 참조와 정책/상담사 근거 누락은 계속 거부합니다. 잘못된 선택·구조에는 각 에이전트당 한 번만 자동 교정을 요청합니다. 올바른 평가 근거를 확인한 뒤 코칭을 호출합니다. 원문 대조 검증을 생략하거나 다른 문장을 임의로 근거로 붙이지 않습니다.

추가 검증은 한글·줄바꿈·여러 공백·따옴표·말줄임표·이모지·긴 원문, 잘못된 근거 id, 정책과 발언의 구분, 고객 발언을 코칭 대상으로 선택하는 오류, 자동 재선택의 성공과 제한을 포함합니다. 실제 SDK 모의 HTTP 테스트도 새 응답 형식으로 갱신했습니다. 실제 유료 API의 응답 품질과 성공은 이 환경에서 재검증하지 못했습니다.

## RAG 비교 도구 점검

12개 고정 예제에서 Before/After 각 12회가 데모로 정상 처리되었고 JSON과 Markdown 수치 표를 생성했습니다. 실제 의미 검색 Recall@4, LLM 정책 판정 정답률, API 비용 절감은 측정하지 않았습니다. 데모 결과에는 해당 품질 지표를 null로 저장합니다. 문서 개수·문맥 길이·로컬 처리 시간만 점검 기록으로 남깁니다.

실제 키로 `python scripts/benchmark_rag.py --repeat 3 --judge` 실행 후 `python scripts/render_benchmark_report.py docs/results/rag-benchmark.json`으로 표를 갱신합니다. 별도 벤치마크 Chroma 경로를 사용합니다. 12개 자체 작성 사례이므로 독립 전문가 평가와 운영 분포 검증은 남아 있습니다.
